# Codex connections

[Architecture index](overview.md) · [Canonical instructions](../../AGENTS.md)

## `src/main/sessions/codex/`

Codex (see Codex below): codex.ts finds the user's `codex` and its version, rpc.ts runs `codex app-server` and speaks its JSON-RPC, login.ts says which login Codex has and what it allows, limits.ts reads its usage limits (account/rateLimits) as usage windows, for both connections, options.ts what a Codex agent can be set to run with (see Agent settings), fake-codex.mjs fakes the CLI; terminal/ and app-server/ hold its two connections (their connectors, fixtures recorded from the real CLI). terminal/: connector.ts starts Codex's TUI on the shared Terminal session with its TerminalCli (tui.ts: its command line, its window title's states, its hooks, pasting in), composer.ts reads its composer's draft, hooks.ts makes its session hooks (commands posting to hooks.ts's server) and their trust, trust.ts checks that trust with Codex itself and usage.ts reads its usage limits, each from a private app server (rpc.ts askAppServer), recorded.ts reads the fixtures.

## `src/main/sessions/codex/app-server/`

The App Server connection (see Codex below): connector.ts starts the app server (the project folder trusted for it alone) and its thread (or resumes it, with its history), session.ts runs the thread's turns (modes, model, effort, interrupts, plans, slash commands), translate.ts turns its items and notifications into session events, prompts.ts answers its requests (approvals, questions, elicitations), commands.ts and diff.ts are its slash commands (and /diff's git), protocol.ts what corrallm sends. recorded.ts reads fixtures/; replay.ts replays one as an app server, for tests.

## Codex

- The registry's `locate()` supplies the user's `codex`; `codex.ts` discovers it only when the override is unset (the standalone installer's ~/.local/bin, then the login shell's PATH; on Windows npm's native `codex.exe`, never its `.cmd`) and checks its version against `MIN_CODEX_VERSION` (0.160.0: what the fixtures and protocol were read from). Codex keeps its own home (~/.codex: config.toml, AGENTS.md, skills, MCP servers, sessions), so corrallm's threads are the user's (`codex resume` sees them, and corrallm can resume theirs).
- `rpc.ts` runs a private `codex app-server` per session over stdio (never the shared daemon a desktop app runs, never `--listen`: its sockets are unauthenticated), says hello (`initialize` with the experimental API, then `initialized`), always sends params (Codex refuses a request without them), answers every request the server makes (an unanswered approval stalls the turn; unhandled methods get -32601), drains stderr, and closes by ending its input, then SIGTERM, never SIGKILL (that orphans what it runs). The renderer never gets raw JSON-RPC or a generic channel: each action gets a typed `session:*` channel.
- Logins: corrallm never reads, stores or passes credentials; Codex uses its own (`codex login`), and corrallm asks its app server only which kind it is (`account/read`, `login.ts`). The App Server connection runs on any login, a ChatGPT plan included, because OpenAI allows it for local apps (learn.chatgpt.com/docs/app-server, Auth endpoints: "If you’ve built a local or open-source application using Codex app-server authentication, you can continue using it… App-server authentication has never been permitted for commercial or hosted services."). So on a ChatGPT login a session's first turn that would use the plan (a message, /review, /compact, /init) first asks (`planPrompt`, quoting that): Yes allows it for the session, "don't ask again" for good (the `codex` consent `plan` in `settings.ts`, through `Consent` in sessions/adapter.ts), No sends nothing; interrupting withdraws it. A build made as a commercial or hosted product (`CORRALLM_DISTRIBUTION=commercial` or `hosted` when building: vite.main.config.mts defines `CORRALLM_DISTRIBUTION`, 'local' by default) refuses a ChatGPT login instead (`appServerRefusal`), leaving the plan to Codex · Terminal, which is Codex's own CLI. Sign in with ChatGPT (developers.openai.com/siwc), which OpenAI recommends instead, is not built: it would have corrallm keep and refresh the user's OAuth tokens.
- The App Server connection (`codex/app-server/`) runs a Codex thread in corrallm's transcript. Rules it keeps:
  - One private app server per session, closed with it, told on its command line that the project folder is trusted, for that server alone, as Codex · Terminal is (`-c projects=…`: `folderTrust` in `codex/terminal/hooks.ts`, by the path its thread works in and, where it differs, the folder's real path; the user's config.toml is never written). Its thread starts (`thread/start`) in the project folder with the approval policy and sandbox of the mode it was given; with none, it passes no permission overrides and reports Codex's actual policy. Modes are Codex's /permissions presets (Read only: read-only sandbox, on-request; Default: workspace-write, on-request; Full access: no sandbox, never) and Plan (Codex's plan collaboration mode, with Default's permissions). Every `turn/start` carries the model and effort; only a chosen mode adds approval policy, sandbox policy (the one Codex reported for the thread when of the same kind: it carries the user's own config.toml settings) and collaboration mode, which Codex keeps, so a mode switched mid-turn applies from the next turn. `clientUserMessageId` is the renderer's message id, so a resumed thread's history (`thread/resume`'s `initialTurnsPage`, its last 30 turns) matches what was shown live. A thread is remembered once it has a turn (Codex keeps none without), and one that cannot be found starts afresh quietly.
  - A turn ends with `turn/completed`. A plan proposed in plan mode is asked about once its turn ends ("Implement this plan?", as Codex's TUI asks): Yes switches to Default and sends "Implement the plan." in the same corrallm turn, so the queues' Run hears its end once the plan is carried out; feedback keeps planning; no feedback ends it.
  - Codex's requests are prompts, answered as its TUI answers them (`availableDecisions`): Yes is `accept`, "always" the decision Codex offers to keep (this session, a command prefix, a host), No `cancel`, which stops the turn. Codex remembers what "always" allowed: corrallm never answers for the user. Questions (`request_user_input`), MCP elicitations (a form's fields as questions, a link) and permission requests are prompts too; a request Codex stops waiting for is withdrawn, and every one is answered.
  - Tools keep the names Codex's model knows (`exec_command`, its command unwrapped from the user's shell; `apply_patch`, an entry per file with its diff; `web_search`; `mcp__server__tool`; `spawn_agent`…: a subagent's thread nests under the call that spawned it). Reasoning summaries are thinking (Markdown), `update_plan` the turn's to-do list, compaction and reviews notices, and command output streams at most every 150 ms. Usage is the last request's context and the plan's 5-hour and weekly limits (`account/rateLimits/read`, then updates; read once, `limits.ts`, for the composer and for the usage readings); errors say what to do by `codexErrorInfo` (log in again, when a usage limit resets, /compact).
  - Slash commands are Codex's (commands.ts), run as its TUI runs them: /review, /compact and /init are turns of the thread; /model, /permissions (never to Full access: see Security rules), /status, /mcp, /skills, /diff (git, run by the core with the repository kept from running anything), /new, /clear, /rename are answered by the session. Skills are slash commands too (`/name` is sent as `$name`, with the skill attached). Pasted images go as data: URLs (the app server refuses remote ones), and not to a model that reads none.
- Interrupting an App Server turn stops the commands it started, as the native CLIs do: the composer's Stop, a token's `session.interrupt`, Kill, taking back a delivered message, a plan prompt's interrupt, and a turn Codex itself reports interrupted all use the same cleanup. corrallm sends `turn/interrupt` while the native turn runs; the plan prompt's native turn has already ended. Its `end` releases another message only after the command cleanup settles. The session records live `commandExecution` items' `processId`s by turn (including a completed item whose process still runs, with no `exitCode`); a `unifiedExecInteraction` with an earlier turn's process does not adopt it, and history from a resume is never included. Once the turn ends, it sends experimental `thread/backgroundTerminals/terminate` for those ids, each `{ threadId, processId }`, never `thread/backgroundTerminals/clean` (which would stop earlier background work). These are Codex's process ids, not OS pids. A `{ terminated: false }` response means the process is already gone. Each request has a two-second bound; a refusal, invalid response or timeout warns in the session with the process id and that its command may still be running, then releases the next turn. A server without the method warns once per session and leaves ordinary interruption working. No minimum-version increase is needed: the installed 0.162.1's generated experimental schema and [0.160.0's protocol](https://github.com/openai/codex/blob/rust-v0.160.0/codex-rs/app-server-protocol/src/protocol/v2/thread.rs) both carry it; [upstream's introduction](https://github.com/openai/codex/commit/a1a8807e9d67fad4b95f2730a9669eca5a9d27d0) first shipped in stable 0.140.0. `command/exec/terminate` is for client-started exec sessions, not the agent's `exec_command` tool.
- Codex · Terminal (`codex/terminal/`) runs Codex's own interactive CLI on the shared Terminal session (see Terminal), so the user has all of Codex in the agent view: its approvals, questions, plans, slash commands, models, @-mentions and images are answered there, and answers, modes and models are refused over the session channels. corrallm checks its version (`MIN_CODEX_VERSION`), then starts `codex --no-daemon -C <folder>` (its own agent, never the shared daemon a desktop app runs; `codex resume <id> …` to resume, and "No saved session found" starts afresh) with overrides for that session alone (`-c`; the user's config.toml is never written): the folder trusted (the folder dialog is the trust gate), corrallm's hooks (`hooks.ts`: UserPromptSubmit, Stop and Interrupt, each a command that posts the event to `terminal/hooks.ts`'s server with the session's token, through `/bin/sh` and curl, printing nothing and always succeeding) and their trust (`hooks.state`, by the key and hash Codex trusts each by: computed as Codex 0.160 does, and checked once per Codex executable and version with Codex itself, `hooks/list` on a private app server, `trust.ts`; without it Codex stops at "Hooks need review"), its window title set to `["activity","run-state"]`, no update prompt, no automatic recaps. Only Read only starts it from its command line (`-s read-only -a on-request`: the connection's one `startModes` entry); Default and Plan leave the user's own defaults (Plan is Shift+Tab in its terminal), and Full access, which never asks, is never a start mode (it is chosen in its terminal). The model and reasoning effort the agent is set to (see Agent settings) start it with `-m` and `-c model_reasoning_effort`. Codex picks its thread id; its hooks tell it (a subagent's are left out). Their permission_mode also reports whether it asks: bypassPermissions (or dontAsk) is Full access, default/acceptEdits asks again, plan is Plan. A switch in its terminal reaches delivery only once the next hook fires; until then the last report remains in force. Its usage limits are read apart from its terminal, never by typing /status into it (see Usage readings and rules).
- corrallm follows Codex by its window title (`tui.ts`): a spinner and Working, Thinking or Waiting is working, "Action Required" waits on the user, "Starting" is its MCP servers starting (a message sent meanwhile is held, and waited for), Ready ends the turn: done after its Stop hook (whose reply is the turn's), interrupted after its Interrupt hook, failed if it took a prompt (UserPromptSubmit) without either (Stop does not run for a turn that errs, as at a usage limit). Nothing it shows outside its screen says why, so before the turn ends its usage is read as after any turn (`readUsage`, a private app server: `terminal/usage.ts`): a window at 100% with a reset to come, where the snapshot's `credits` say Codex has none to go on with (neither `hasCredits` nor `unlimited`, as recorded on a plan without credits; `codexUsedUp` in `codex/limits.ts`), made it fail on its plan's limit (`usage-limit`, until the latest such reset); otherwise it failed for a reason corrallm can't tell (`error`). What its TUI prints at a limit is not recorded, so its screen is not read for it. Its composer (`composer.ts`) is where its cursor shows (Codex hides it during dialogs): a message is pasted in there (bracketed paste, without control characters, then Enter a little later) only while it is drawn and empty, and only once its title has said something (it says nothing while a startup screen is up). Its Enter is not held until the composer shows the message (no `waitsForEcho`): 0.160.1 sends on an Enter read in one go with the paste, as keys that piled up while it was busy are.

## Tests and recordings

- Codex: what the real CLI did is recorded in `sessions/codex/app-server/fixtures/` (its app server's JSON-RPC, both ways, with timestamps: the handshake, models and limits; three turns with a command, an approval, plan mode, `thread/read`; and, recorded through corrallm's own App Server session, a patch and a command with /diff, /status, /mcp and /skills, an interrupt, a pasted image, a resume with its history and /compact; and, as asked for an agent's settings, config/read and model/list, `options`: the connector's tests replay corrallm's own (patch, interrupt, image, resume) through `replay.ts`, which plays back only the JSON-RPC, whatever command line the server was started with, and reports every request the recording did not make at that point, and each of those tests expects no report (a `config/read` a recording lacks, as role reconciliation asks before a resume, it answers with an empty config; the interrupt recording predates corrallm's per-command termination, which its replay explicitly answers as unsupported: the test checks the exact added request and warning, while real-child tests prove termination on a peer that supports it); the tests of what reads Codex's messages (the translator, prompts, slash commands, limits, options, Codex · Terminal's usage reader) take them from the recordings one by one, through `recorded.ts`) and `sessions/codex/terminal/fixtures/` (its TUI in a pty: everything it printed, its window titles, the hooks it posted, the keys sent; two sessions of prompts, one of them corrallm's own (`turns`: an approval and an interrupt, with no view, so its composer is unshaded), a resume, and a resume of a missing session; `recorded.ts` reads them). They were recorded with Codex CLI 0.160.1 and GPT-6-Luna (low effort) in a scratch folder, paths, names, account and the user's own MCP servers replaced with stand-ins of the same length. `sessions/codex/fake-codex.mjs` is a fake `codex` (`--version`, `app-server`: what a message starts with makes it run a command, patch, ask, plan, fail or crash; it keeps threads in `FAKE_CODEX_STATE` to resume them, and is logged in as `FAKE_CODEX_LOGIN` says: an API key, ChatGPT or none) in the same shapes; its slow and background commands are real sleeping Node children (with separate app-server process ids), stopped individually by terminate and all reaped when the fake closes; tests run it with node, and `e2e/app-server.e2e.ts` runs the built app against it (`CORRALLM_AGENT_PATHS`).

- The Codex Terminal connector's tests replay those recordings into a real Terminal session (`codex/terminal/session.test.ts`: each pty plays one back, in order, waiting wherever keys were sent until the session sends the same), and `e2e/codex-terminal.e2e.ts` runs the real connector with `CORRALLM_AGENT_PATHS` pointing at `e2e/fake-codex-tui.mjs` (Codex's TUI in its real formats, running its `-c` hooks as Codex does, only if trusted as Codex trusts them; its app server answers hooks/list, account/rateLimits/read, model/list and config/read) in a real pty.

## Native IDs and safety

- Session ids are UUIDs (`sessions/id.ts`), checked in hook signals, resume IPC arguments, remembered sessions loaded from disk, and both Terminal CLIs' argv builders.

And no message takes Codex's App Server out of its sandbox: `/permissions full-access` is refused, since Full access is the mode menu's, which asks first.

The App Server's `/diff` also disables external diff, textconv and filter drivers; file suggestions must never run a repository's fsmonitor.

Codex's hooks are given and trusted for its session alone, on its command line: corrallm never writes the user's config.toml, and never runs Codex with `--dangerously-bypass-hook-trust` (which would also run the user's and the project's untrusted hooks).
