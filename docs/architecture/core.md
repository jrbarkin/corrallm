## `src/main/`

Main's entry is index.ts; security.ts, app-protocol.ts, csp.ts and url-policy.ts hold the security baseline. ipc.ts checks the preload's core:connect handshake; main owns windows and native UI, and hosts the core process.

The packaged app's [update checker](updates.md) lives in updates.ts and host/updates.ts, never the core or CLI. Its native Restart action goes through the same quit path as a quit (below), its shutdown barrier prepared for `update`, before installation. A Linux release-page choice uses main's private `openLink` core request, served by `WindowPorts.openLink` through the existing `link.open` operation for a connected window; it shares links.ts's policy rather than opening a raw response URL.

How corrallm ends is one coordinator, `src/main/host/closing.ts`'s QuitCoordinator (B14 C2, C4; B11 Design §8, §16.5), which index.ts wires to Electron and the core's link, by reason: `user` (Cmd+Q and the app menu, the Dock's Quit, the menu-bar item's or tray's Quit, and any before-quit it didn't start: main can't tell its own signal from Cmd+Q), `last-window` (Linux and Windows: the last window's `close`, prevented and decided before that window is destroyed; of two closing together, the second is the last, since a window closing is one whose own close is saving or approved; a window destroyed without its close, `window-all-closed`, counts too, a window made to ask on), `update` (Restart to update, `requestQuit`) and `system` (below). While the core's presence is `busy`, or there is none (a core coming up), it asks first, holding nothing while it asks: the question, worded by its cause from the bounded counts alone ("N agents are working.", "A run is going on N canvases.", a job generically, or that it couldn't check; at most "99+", never "0 agents"), is always a sheet on a corrallm window, the focused one else the first not itself closing, restored if minimized, or on macOS with none open a window the reopen service makes, so the system can withdraw it (`showMessageBox` with an AbortSignal: a parentless box on macOS runs synchronously). Quit and pause (default; Restart and pause for an update, with only Cancel beside it) is the save below, work not rechecked; Keep running closes every window on macOS (each flushing its drafts as a window close does) and minimizes every window elsewhere, the core, its endpoint and sessions untouched, and stays Keep running if the work ended while it asked; Cancel (Esc, a withdrawn sheet) changes nothing; any answer but Quit and pause clears an update's restart (`cancelRestart`). With nothing at work it saves at once, the core holding its barrier only if still nothing is (`prepareShutdown(reason, { ifIdle: true })`: presence's `busy`, checked and held in one synchronous step), else answering `busy`, and it asks then: work started since main last heard is never cut off unasked. The save (`Closing`, beside it) is: each window finishes the drafts it composes (`flushDrafts`: over its own port, at most 5 s each, a crashed one skipped), then the core prepares its shutdown barrier (`quit` or `update`). Any of those failing is the failed-save question, a sheet too: Keep corrallm open lifts the barrier (`cancelShutdown`), so the endpoint and every turn go on; Quit anyway, or all of it done, commits it (`commitShutdown`), supervision stopped first, and only then does the app quit or an update install. While it asks, another user, last-window or update request joins the question (focusing it), and the window it is a sheet on stays; while it saves, a second user quit is the explicit five-second escape and an update or last window waits; once approved, before-quit and window closes stay prevented until the core has closed. A window's close is otherwise a view close: it only flushes its drafts, on macOS always (no question). Reload, crash, close and switching canvases detach views and terminal attachments; their run and sessions continue in the core. The system's path (C4) asks nothing: macOS's and Linux's powerMonitor `shutdown` (prevented; macOS posts it for a logout too), the core's `exiting` (it closes itself on a signal: a Linux logout signals main and the core at once, and `pnpm dev`'s Ctrl-C both), a core exiting 0 unasked (`CoreSupervisor`'s `closedItself`), and on Windows (held for B29) a window's `query-session-end` or `session-end`. It stops supervision, withdraws any question, gives drafts at most `SYSTEM_DRAFTS_MS` (a second, `flushDrafts` for `system`), prepares the barrier for `system` and commits it (a failure said without values; what is on disk stands) and quits; a quit already approved finishes instead, installing nothing; a core that closed itself and exited 0 counts as closed. Five seconds after the signal (`SYSTEM_BUDGET_MS`), main exits whatever is left: 0 if the core closed, else 1, saying so once; a CLI the core couldn't end in time is Children recovery's at the next start. `macShutdown: 'at-once'` is C4's tested fallback, not shipped: if the signed logout check finds macOS cancels a logout for a prevented event, `shutdown` is let go, the core asked to save without waiting, and the quit let through at once. Reopening (C10's main half) is the coordinator's one service: Dock activation with no window shown, `second-instance` (the single-instance lock's), and the menus' Open and a notification's click (X6's) restore a minimized window, else show the first, else make one (one at a time: concurrent asks share it); while it asks they focus the question, and once a quit is saving or approved they do nothing. A click's opaque handle goes with `activate(handle)`: a window shown, then the core asked `activate(window, handle)`, which tells that window, over its port, what to show (`show`; the core's notifier maps the handle, below). Main's Dock, menu-bar and tray presentation and its native Notification adapter (X6) read `approved`, `saving` and `asking` for Pause all's state and call `request('user')`, `reopen()` and `activate(handle)`.

The Electron-free services here are composed only by core/core.ts: canvas.ts asks which canvas file to open or save as and which canvas a file is (core/canvas/documents.ts reads and saves it), project.ts keeps project folders, memory.ts remembers each canvas's file, folder and agents' conversations (by the workspace each CLI ran in) and run-journal.ts journals runs and where each party has read to (both in the core's database, core/store/), settings.ts keeps app consents, api.port and whether OS notifications are on (`notifications.enabled`, B14 C11: absent, not a boolean or unreadable is on; `notificationsEnabled()` reads it, unknown fields beside it written back as they were; B22a adds the setter, yours alone), usage.ts keeps readings, exhaustion and spending rules in usage.json, and whole-file.ts writes and reads the files written whole (canvases, api.json and the JSON stores that stay files).

Their state reaches the GUI through operations, topics and the fixed terminal screen stream served by core/terminal-events.ts.

Canvas memory retains failed ordinary updates for retry (native conversation IDs must not be lost). A change with an atomic SQL callback (`setFile` while saving, or `forget`) instead restores its previous pending memory and emits no notification if its write fails. Later memory changes wait for that atomic write to settle, so none can persist a rejected file association; earlier ordinary updates still retry. Notifications of a successful atomic change follow its durable commit.

`src/main/core/workspaces/resolver.ts` is the working-directory seam, composed once by createCore. `WorkingDirectoryResolver.workingDirectory(canvas, agent)` returns ready with a core-owned TrustedPath, workspace (or null), active binding generation and branch (or null), or held with a reason, sentence and optional NeedId. `onAvailability(canvas, listener)` hears when any agent's result may have changed. The legacy `ProjectDirectories` uses ProjectFolders.of: the picked folder, workspace null, generation 0 and branch null, or held no-project. It remains the non-repository/test implementation; createCore uses WorkspaceDirectories over discovery, provisioning and setup (see Workspaces). ProjectFolders notifies when choose, restore or forgetting its canvas changes its folder; restoring the same valid pick leaves discovery cached, so cancelling its dialog changes no workspace state. A lost pick is cleared and announced once. Core close removes its memory subscription.

Session launch (including a restart or launch after Fresh), conversation listing, resume validation and conversation rewind use the agent resolver. Canvas-wide reads name no agent: its separate `projectRoot(canvas)` accessor supplies settings/options defaults, file pickers without agent context, reveal's base containment root, headless canvas admission and comparison of old and newly picked project roots. Options without a root still read the user's home defaults. The accessor preserves project-wide search and containment rather than choosing an arbitrary agent. Agent-context options and file searches resolve that agent's verified tree. The mutation gate includes window-owned native sessions and their current activity as well as core runtimes. A pending rebind card is available in either host. Conversation records use the active workspace namespace, pinned for a live session; non-repositories use PROJECT_WORKSPACE. The session manager checks generations itself (see [Sessions](sessions.md)): a session is installed, reused and given work only while the binding it launched in is the active one, a held directory (a pending rebind) keeps its session without new work, and its live claims on native conversations (`ConversationClaims`, composed here once) keep two agents' sessions off one conversation.

## `src/main/core/`

The core: corrallm's one server, owning profile stores, canvas documents, runs, messages and sessions, in an Electron utility process in the app and under plain Node headless.

The process owner (`src/main/core/children.ts`) keeps its recorded PID/start/group checks before signalling and again before SIGKILL; after an EPERM group signal or probe it counts the group as gone only when a bounded, complete process-table read finds no non-zombie member, retaining cleanup failures when a live member remains or inspection fails (the CLI test helper shares that membership check).

Electron-free: it never imports Electron or src/main/host/ (ESLint's app/boundaries-core); what differs between hosts is passed in. host.ts is HostServices, what it asks of the app that hosts it (dialogs, links, file reveal and run-save acknowledgements), and TrustedPath, the only paths a canvas is opened from or saved to and the only project folders; entry.ts, the core process's entry (core.cjs): main asks it `init` for the app (it takes core.lock first, and while `serve` holds the profile answers who does), then hands it each trusted window's port beside the link, which gui.ts serves over createCore(config, appHost(link)); main passes the profile, distribution, locale and unpackaged fake-session setting. Once composed, it always serves the profile's outside endpoint (`src/main/core/endpoint.ts`, B11 Design §16.6: MCP on 127.0.0.1 on the port the profile keeps, see [Headless](headless.md)), one that can't listen said as a status, never a dialog; then the token socket for `corrallm token` (token-socket.ts, answering as `owner: 'app'` with the endpoint's URL, or with none and why, `unserved`); then api.json, naming this process. Committing the shutdown barrier closes the socket and the endpoint (requests going on ended, api.json removed if still its own) before the core closes; as the process exits, both are removed; a socket it can't serve is said, and the app runs on without it.

In the native self-test it only runs the checks. Told SIGTERM, SIGHUP or SIGINT (a Linux logout signals main and the core at once: B14 C4), the core process closes itself as `serve` does and as main's system path would: it emits `exiting` to main, gives every window it serves at most `SYSTEM_DRAFTS_MS` (one second) in all to land its drafts, prepares the barrier for `system` (a failure said without values, no dialog) and commits it, the same close main's `commitShutdown` shares, then exits 0; a signal again meanwhile changes nothing, and before it holds a profile it exits at once. The core's presence (B14 C5, C6: `src/main/core/presence-publisher.ts`, composed once in createCore) is counted from its own state, never a window's topics: over every canvas Engines runs, `working`, agents in a turn (a session working, or waiting for you mid-turn); `runs`, canvases whose run is running (waits and per-agent pauses included); `jobs`, the worktree setups running or waiting to (`SetupService.jobs`), the worktrees being made or removed (the provisioning queue's size, which says each change), each message being handed to an idle session (`delivering`; one queued behind a turn is that turn's), and each live background task a session reports (`Session.tasks`, including while idle); `needs`, the distinct items `waitingFor` holds for you on each canvas (`for === 'you'`, so a lead's copy doesn't count, a shared setup's card once); `busy`, working + runs + jobs above zero, what quitting would cut off; `notify`, whether OS notifications are on (the one field that isn't a count: `notifications.enabled` as the notifier reads it, absent or unreadable meaning on, cached from the settings as they change and sent again, as a revision more, when it does), and `awake`, while something goes on without you: a session working, a setup/workspace/delivery job, or a running run's own timer (a delay, a wait's limit, a usage reset, for an agent no pause holds: `nextDue`, what the run's alarm is set for), never a turn waiting for you, a pause, a background task alone, an open session or a listening endpoint. A reported background task therefore makes `busy` true and `prepareShutdown(reason, { ifIdle: true })` answer busy, so quitting asks (the existing generic jobs sentence); ending the last task makes an otherwise idle core idle again, without changing `awake`. It holds no names, ids, paths or text. The first snapshot (revision 0) goes to main before the app's `init` answers; after that it is counted again when the publisher marks a canvas's `needs:` or `worktrees:` changed (`TopicsDeps.marked`), the runtime source a canvas's run, sessions or messages, a canvas opens or closes, or the queue's size changes: at most one snapshot per 250 ms, trailing, whole, sent only if it differs, each a revision more. `Core.presence()` counts now and sends that first if it changed, as ifIdle does. A host that fails to take it is logged and never holds the core up; it stops at close.

Background-task presence follows the connection's reported whole live list, without guessing from a transcript or terminal output. The Agent SDK's `background_tasks_changed` list supplies it; `task_started` associates a task with its tool, and `stopTask` requests a stop whose native list update removes it. Ambient SDK tasks are already filtered out by the adapter. The App Server tracks command process ids only for a turn's interruption cleanup, not a session-wide live list after that turn ends. Neither Terminal connection maintains such a list (individual Program Status task records are not a whole live set). Those three connections therefore contribute no background-task jobs when otherwise idle; their reported turns still count normally. A native session closing clears its task list.

Each `forkCore` calls a handler factory with its own CoreProcess. `CoreSupervisor.owns` covers initialization as well as the running process; desktop requests check that identity before the service and again after it settles, and presentation events from a replaced process are ignored. A process keeps only its own bounded, increasing presence snapshots. `CoreSide.active` is gone: presence's `busy` replaced it. Main takes `exiting` from the core it runs now, and a core exit with code 0 it didn't ask for, through the system's path (above); `CoreSupervisor.presence` is the presence of the core up now, none between a crash and the new core's first.

The words are `src/main/core/notification-text.ts`'s (C8): the title "corrallm", and one fixed sentence by what the item is, read from its kind and id, never its title or detail ("{agent} is asking you something", a prompt or a stalled turn's; "{agent} is waiting for you", a hold; "{agent} couldn’t start", a session that won't; "A worktree’s setup is waiting for you"; "A change on {canvas} needs your answer", a proposal or a workspace change's Switch; "{canvas} changed on disk"; "{canvas} needs you", anything else, a canvas-wide hold among them; "The run on {canvas} finished" or "was stopped"; several, "N things need you"), carrying only an agent's name (as the app shows it) or a canvas's (its file's name, a draft "Untitled"), each NFC, then only letters, marks, digits, spaces and `- _ , ' ( ) #` kept (anything else a space: no markup, URL punctuation, control, bidi or zero-width character), spaces collapsed, trimmed and cut at a grapheme to 32 UTF-8 bytes with "…", an empty one "An agent" or "A canvas"; the body at most 160 bytes. ## Native presence in main (B14 X6)

`src/main/host/presence.ts` projects the current core's bounded presence into one fixed menu model: status/count rows, Needs, Open corrallm, Pause all and Quit corrallm, plus Recovering and the fixed unsaved-pauses warning. The Dock and tray use the same model. Pause all invokes the existing fixed host request once and is disabled without presence, while that request is pending, or while the quit coordinator is saving or approved. The coordinator's optional presentation callback announces state changes without changing its lifecycle decisions or polling.

`src/main/host/electron-presence.ts` supplies the Electron backend. macOS retains its Dock menu and Needs badge (empty at zero, then 1–99 or 99+), and a template-image menu-bar item exactly while no window is visible and unminimized; its title is the working count, empty at zero. Linux keeps its tray for the app's lifetime, with both a fixed Open item and click activation, and uses the shipped corrallm.desktop identity for launcher badges. Keep running and reopening remain the quit coordinator's. Windows tray and notification shipping remain held for B29. The hidden e2e host creates no tray, sets no macOS badge and requests no native notification authorization.

The backend holds at most one prevent-app-suspension power blocker while the core reports awake. A lost core clears it, and every main exit path stops it; quit approval alone keeps it active while the core finishes closing. A failure is logged without values and does not affect the core. A failed start is not retried within the same awake episode. The display may sleep, and closing a laptop’s lid still sleeps it; the headless host keeps nothing awake. Window visibility and focus events update presentation and report focus to the current process, including its initialization; no renderer subscription or activity estimate is used.

`src/main/host/notifications.ts` holds native notifications by opaque core handle, constructs only the supplied bounded title/body, rechecks focus immediately before show, and routes a click once through the coordinator's activate service. Unnotify, core exit and quit close held objects; late clicks cannot target a replaced core. Show or failed events settle the attempt; no show event within five seconds fails it without retry. At most 256 native objects are held, with duplicate live handles sharing the original result. Native error payloads are never forwarded or logged.

The C9 authorization seam is NativeNotifications.prepare(working, enabled). Main's host services hand it each validated presence snapshot's `working` and `notify` (`src/main/index.ts`): the first snapshot with an agent working while the core's notifications are on is the only cue, never a launch, a restore, a token-readable settings result or an incoming notification, so an idle core, a profile with notifications off or a core that has not started anything asks the OS for nothing. The shared native backend checks support once per main process, so a replacement core's adapter learns its support from that answer and never prompts again; until its own first such snapshot it reports unsupported. The core retains eligibility, preference-off withdrawal, rate limiting, sanitized fixed text and destination mapping; the native adapter implements none of those policy decisions. A notification's `activate` leaves main as the click's opaque handle alone, through the quit coordinator's reopen service.

At the final native send boundary, `Engines.sending` checks the text after withdrawal notes against the receiving native session’s `fileMentions` declaration, using the kept run origin or other-party sender. Manual typing passes.

Prepared B21 party targets use the canvas lane: `scopeOf` assigns an agent-scoped operation whose `to` is an object to its canvas, preserving the existing lanes for string agent ids and group targets. The AttemptId vocabulary names a core attempt; without a composed resolver a token reaches none.
