## `src/renderer/`

React UI. index.html is the Vite root; global.d.ts types window.api; open-link.ts api/bridge.ts unwraps GUI results, preserving errors' code and sentence across contextBridge; api/client.ts awaits drafts before every GUI op and its returned topic revisions before resolving a write. api/topics.ts mirrors immutable topic state for useSyncExternalStore, re-subscribing on a new core epoch or a revision gap; test-api.ts supplies a fake core and expectOneOp for gesture tests. open-link.ts is where clicked links go (the core’s link.open, or link.reveal for a file:// link; provided by App.tsx). catalog.ts holds the catalog the core gives (catalog.get), which boot.ts loads before the app mounts (main.tsx), so the renderer's views read it at once (catalog(), and its lookups: an adapter's connection, its view, what it continues in; never the engine, which is given its own: src/shared/engine/catalog.ts).

## Prepared runtime topic views (B11 X10)

`src/renderer/api/topics.ts` also accepts the prepared `run:<c>`, `sessions:<c>`, `messages:<c>` and `session:<c>:<encodeURIComponent(agent)>` contracts. These are dormant: no production component subscribes, and the registered topics and GUI schema remain unchanged until C8. `src/renderer/api/topic-wire.ts` supplies the additive source type and pure patch application. Its key helper validates the model's canvas id against the prepared API brand and uses the shared encoder, never hand-sliced agent ids.

At that receiver seam, `topicsSubscribe` returns a whole snapshot or the transfer's `begin`; subsequent `chunk` and `end` frames arrive through `topicsOnChange`, in port order. A live change that cannot fit bounded deltas may start the same replacement transfer with a `begin` event; the mirror stages it atomically as it does the initial snapshot. Frames arriving before the subscribe promise resolves are buffered. A transfer is scoped by topic, epoch and snapshot id. Each chunk has an `index` starting at zero, and `begin.count` counts chunks, not entries (B11 §16.3a). The mirror stages unique keyed entries only from consecutive indices and checks retained-entry references; it installs only at `end { rev }`, once all declared chunks arrived exactly once in order. The previous complete snapshot remains visible meanwhile; it never acknowledges a partial revision. The 1 MiB frame limit and its one exception, an entry alone in its chunk that no frame holds with the chunk's envelope, use the shared size check (`snapshotFrameFits`). Whole runtime snapshots exceeding the limit require chunking too. No entry, prompt or plan is clipped.

An unexpected frame, repeated/skipped/swapped chunk index, duplicate key, mismatched transfer, inconsistent order, missing append target, delta during an active transfer or ten seconds without transfer progress rejects revision waiters as unavailable and schedules a new subscription after 100 ms. The last complete state remains visible. Epoch changes reject old waiters, abandon transfers and ignore old responses; revision gaps resnapshot, duplicate revisions do not append twice, and a seq jump on another topic is legal. Deferred release preserves StrictMode's one subscription and clears transfer/retry timers when the last observer leaves.

Run patches set/remove agents and update only supplied top fields (`null` removes optional top fields). Session-summary patches set/remove agents. Per-session upserts replace entries, new ids append in upsert order unless an explicit order is supplied, and text appends target retained text/thinking entries only. An authoritative history order drops unreachable entries. Message patches set/remove items, preserve surviving order and append new ids in set order unless an explicit complete order is supplied, and update the cursor when supplied. Equal entities retain their objects across patches and fresh snapshots; an ordinary text append does not scan history or rebuild its order.

`src/renderer/api/runtime.ts` exposes read-only hooks for the run, summaries, a session and its ordered entries, and mailbox messages involving an agent (incoming or outgoing, in core order). They read only the mirror, with no local engine fallback. The ordered-entry selector keeps its array through summary-only changes. `src/renderer/test-runtime-core.ts` supplies independent snapshots from the shared run/session/message projections and bounded history chunks; its fixtures include resolvable attempt/message, delivery/user-entry and child/parent-entry references.

**C8 integration contract.** The prepared per-session `summary`, when supplied, is the complete authoritative DTO, not a partial merge. Ordinary text appends patch entries without republishing or recomputing the summary. `begin` and its bounded summary must fit within MAX_TOPIC_FRAME. A publisher that cannot fit them refuses the subscription with an error, before emitting any frames; it never clips or splits the summary. The fake publisher enforces this, including rejecting an oversized non-reply field. SessionSummary.reply itself is capped at 4 KiB of UTF-8 by the shared projection and schema, with replyCut indicating more in the transcript. Subscription errors reach revision waiters and keep the last complete snapshot visible. The mirror also defensively rejects malformed oversized begin frames. Chunk indices detect swaps, gaps, repeats and excess chunks; a missing end still times out. Deltas buffered before the begin response are replayed after end and ignored when its revision already includes them; deltas sent during an established transfer are refused. Run holds are keyed agent/group entries (`agents[id].pauses` and `groups[id].pauses`); run transfers namespace their keys as `agent/<encoded id>` and `group/<encoded id>`, with no holds in the begin summary. The core's publisher (`src/main/core/topics.ts`) sends this, every port batch within the frame budget; X9 wires the response/event seam when it widens the live GUI schema (`topics.subscribe`'s request and answer, GuiApi's and the preload's `topic` event).

## `src/renderer/graph/`

Graph editor on React Flow (@xyflow/react).

Its nodes are agents (type 'agent'); groups are type 'frame'.

Structure operations live in src/shared/model/structure.ts; flow.ts projects the canvas topic's immutable rows into model nodes and React Flow views, memoized per entity object (fromRows reads only a changed node's rows; unchanged nodes, queue items and edges keep their objects).

GraphNode is a view type, never the model read by the engine or widgets. selection.ts keeps selection outside the document; marquee start clears React Flow's internal selection too, so a node selected before the marquee is included in its first change.

Empty canvases never queue a fit that would move their first added node. overlay.ts holds measurements and a drag until its one canvas.move lands at drop, fitting containers for display while dragging; a dragged node is held in canvas coordinates, placed in its parent as projected, so the commit that refits its groups shows it where it was dropped even while the overlay still holds it.

CanvasSource keeps the shown canvas's subscription through restores and switches. A same-canvas Open preserves its view, sessions and run token. Every failed switch restore shows Canvas recovery; non-moving Needs replies flush first without the switch's inert barrier. Failed reply cards remain retryable while their item is live, then disappear with their badge count when the topic removes it; successful outcomes remain until dismissed, or until the topic raises their id again after removing it (stalled/<agent> is reused for each silent turn): that item is new, so it shows its choices and counts in the badge.

The Needs popover also renders the core's human-only worktree setup cards, with Run, Always, Skip, Stop or Retry as offered, answered through one `reply`. Card details preserve spaces and line breaks so a setup command's quoted whitespace and its separate preview fields are shown as the core sent them. A setup's id remains live across starting, stopping and retrying: its current choices replace a previous reply's outcome rather than hiding Stop or Retry behind an old settlement.

GraphEditor reads name, project, edited and arrange from the mirror's meta; the canvas in GraphEditor.tsx (node views in nodes.tsx); an agent's queue (QueueEditor.tsx, its items in src/shared/model/queue.ts, SortableList.tsx and sortable.ts) and questions (Questions.tsx), shown in its agent view; agent types and their actions (sourced catalogs) in agents.ts (and runCatalog, the catalog the engine is given); the canvas's Needs you sidebar (Questions.tsx's QuestionsSidebar) shows what waits for the user as src/shared/engine/needs.ts derives it: the run's holds (AskCard), then what agents' sessions ask (their questions, answered there; anything else, with Open session), then what Terminal agents' CLIs ask; times (a delay's, a wait's time limit: one Time model in model/queue.ts) read from what is typed and turned into deadlines in model/time.ts, and worded in model/words.ts; a repeat (QueueRepeat: steps, messages, waits and delays run in rounds until a condition holds, at most `rounds`, then ask or go on; or, `until` a RepeatEnds, going round with another agent's repeat) is one item holding others: findItem (model/queue.ts) finds an item at any depth, and queue-ops.ts's edits reach its list by id (the core's queue.* ops build on them); automatic layout (dagre) in src/shared/model/layout.ts is applied by the core's document operations, with geometry from src/shared/model/geometry.ts and fixed CARD_SIZE boxes; React Flow measurements stay in the view.

Structural gestures each call one generated api.canvas* operation, whose promise waits until the mirror reaches its revs.

Delete shows the core's cleared-reference sentences.

Stored edges are links (agents that can talk); arrows for the work one agent's queue gives another are derived from the queues (src/shared/model/work.ts, opened in WorkDetail.tsx).

Drawing an edge asks which (ConnectMenu.tsx).

Canvases save as .corral files (versioned JSON, version 2, holding the canvas's id: see Canvas identity; format and validation in src/shared/model/file.ts, which reads a CanvasDocument against the catalog; the top-left float in CanvasMenu.tsx, whose New, Open, Save, Save As and project folder call `canvas.create`, `canvas.open`, `canvas.save` (`canvas.saveAs` for a canvas never saved), `canvas.saveAs` and `project.choose`, New and Open as a switch: see Run recovery and persistence; an agent's adapter, connection and settings, by adapter, among what it saves: see Agent settings). src/shared/examples/ holds .corral templates, listed in src/shared/examples.ts.

ExampleGallery.tsx reads their fields and agent roles through templates.list; a test keeps each one valid and written exactly as toFile writes it.

A template may leave blanks ({{key}}, filled from its `fields`; src/shared/model/templates.ts) and leave agents' types open (no `adapter`: the default, or chosen when it is used; withAgents translates steps between types by their catalog jobs through model/agent-ops.ts).

The gallery's form also chooses how each agent runs (withConnections): by default in a Terminal by native default (`defaultConnection`); missing installed CLIs are labelled without falling back to fake work.

A template's tool steps say what they are to do (`instruction`, which may hold blanks too), as does Codex's /review: a test keeps it so.

It opens as a new canvas or is inserted into this one as a group through api.canvasInsertTemplate (model/insert.ts in the core, which fills fields and mints every id); New calls api.canvasCreate with the template and choices, making the template the canvas itself, retaining its node ids, with no enclosing group and no project folder inherited.

It leaves the previous canvas open, keeping its unsaved work and folder; creating another template therefore needs no discard confirmation.

## `src/renderer/agent/`

The agent view (AgentView.tsx), opened full-screen from an agent on the canvas: the agent's native questions and queue, showing live manual submissions as read-only Message rows (model/queue.ts' SubmittedMessage, queues/submissions.ts' display-only projection; the core keeps them as your messages and restores them with the run); a restored chat with no live submissions is named by its first message (model/session.ts' chatStart, by the `conversation` each message is marked with, its native CLI's, since its last /clear), left of a Claude Code-style session (Transcript.tsx, its replies' Markdown in Markdown.tsx and blocks.ts, a tool call's diff or output in ToolDetail.tsx, tool words in tools.ts; Composer.tsx, completing slash commands and @-mentions: completion.ts), or a Terminal agent's terminal (src/renderer/terminal/).

A rail at its right edge (Rail.tsx) spawns an agent from the one shown (api.canvasSpawnAgent: a peer beside it, or one linked below it) and stacks the others opened that way, to switch between.

GraphEditor keeps the stack (the agent shown first) and clears it when the view closes. motion.ts animates the panel: out of its canvas card and back, minimized into the rail, grown out of the ⊕ or a stacked card.

Its agent chip sets the agent's adapter and connection (agents.ts: connectionsOf, Terminal first); beside it, a Terminal agent's settings (Settings.tsx: the model, effort and mode its CLI starts with, in ChoiceMenu.tsx's menus, the composer's too, each adapter's modes as modes.ts names them); an Agent SDK agent's chip also offers Continue in Terminal, and so does its composer for a command only Claude Code's terminal runs (commands.ts: /permissions, /login, a bare /config…, completed "In Terminal" and never sent to the SDK session; and a shell command for its bash mode, "!" first, bashCommand): the agent switches to Terminal, which resumes the same session, and SessionStore.sendOnceIn runs the command there (a "!" message is typed into Claude Code's prompt like any other, so the renderer still passes no command line: running one in main, for the Agent SDK, would need the security rule changed first).

The view answers some commands itself for an Agent SDK agent (commands.ts' VIEW_COMMANDS), in a panel above the composer: /resume (ResumePicker.tsx) picks another of the project folder's conversations to open in the agent (SessionStore.resume: main makes it the agent's own, the transcript empties, and the session starts again resuming it, its history filling the transcript), /mcp (McpPanel.tsx) lists its MCP servers to reconnect, disable or enable (signing in to one is Claude Code's /mcp, in Terminal), and /rewind (Rewind.tsx; also Esc twice in an idle Agent SDK agent's empty composer, as in Claude Code, where one Esc still closes the view half a second later, and "Rewind to here" on the user's messages since the last /clear that the CLI has: rewindPoints) previews what restoring the files to before a message changes, then restores the code, the conversation or both (SessionStore.rewind; the message goes back into the composer to edit); Esc closes such a panel first.

An MCP server's request shows in the transcript (Elicitation.tsx: a form, or a link to open through main).

It shows the session the engine keeps for the agent (src/shared/engine/delivery/mailbox.ts, read with useSyncExternalStore, so turns play on while the canvas is shown), whose model is src/shared/model/session.ts.

## `src/renderer/queues/`

Every agent's queue side by side, task by task, laid out like a diff viewer (QueuesView.tsx), from the canvas or an agent. lanes.ts aligns rows so a wait sits below what it waits for, links waits and work handed over, and finds waits stuck in a loop; ribbons.ts shapes the ribbons in the gaps between lanes that join linked tasks (from where the view measures them); `src/shared/model/queue-marks.ts` marks tasks (links, the run, a repeat's round) wherever a queue is shown.

A repeat is one cell spanning the rows of what it holds (Cell.span, Cell.inner): the cell, its card and its list are CSS subgrids of the lanes' rows, so each item sits in its own row, level with the other lanes.

## `src/renderer/terminal/`

A Terminal agent's session in its agent view (TerminalPane.tsx): the CLI's own terminal (xterm.js, screen.ts), linked to main's (link.ts, backend.ts), with a bar of what the run asks of the user, the session's last warning (until dismissed), what the session does, its queued messages, the queue's ⊕ and, on a Mac, whether Option works as Meta (keyboard.ts).

Files dropped on it are pasted as their paths.

The terminal draws only with xterm.js's WebGL renderer: the production CSP blocks its DOM renderer's inline styles, so that renderer must never draw it. screen.ts checks that the page can make a WebGL2 context before the terminal opens, and replaces a context the GPU loses. Where there is none (a virtual machine without 3D acceleration, remote desktop, a blocklisted GPU), as it opens or when the lost context cannot be replaced, the terminal is disposed of and its place says that it needs WebGL2 and what to try (turn on 3D acceleration, use the computer's own display, update the graphics driver, then reopen the view or restart corrallm). The view goes on undrawn: snapshots count as shown at once, and the CLI keeps running in main. A fallback renderer may come later; it must not weaken the CSP.

What its Claude Code asks in it is listed in the canvas's Needs you sidebar (Questions.tsx's TerminalAskCard: shown, never answered; Open terminal; a permission with what its prompt shows, in short: the command in full, an edit's diff, the start of a new file), and its card glows while it asks anything; its folder trust dialog, asked as it starts (turn or not), makes the bar say "Trust this folder in the terminal".

A file:// link Cmd-clicked in it is shown in the file manager if it is in the project folder (link.reveal).

## `src/renderer/search/`

Reusable type-to-search: search() ranks matches, SearchPicker is the dropdown (its `typed` lists options read from what was typed, such as times, first).

Queues: there is one queue component, QueueEditor.tsx. Every queue the app shows (an agent's own, the one shown beside it to pick from, the work panel between two agents, the lanes of All queues) is built from its rows (`QueueRow`), its end (`QueueEnd`) and its picking (`PickTask`), styled once in GraphEditor.css (cards at rest; what edits a task shows on the one pointed at; the drag handle always shows). Queue writes use `operationEdits` in graph/edits.ts over the generated `queue.add`, `remove`, `move` and `update` client calls; `editsOf` binds them to one agent. A row drag previews a local order and sends one neighbour-based move at drop, retaining the preview until the mirror acknowledges it; cancellation sends nothing. ArrowUp/ArrowDown on a row's handle send one move at once. Chromium blurs the focused handle when the reorder's render moves its row, and React's commit focuses it again, so the next press still moves it: `src/renderer/graph/sortable.test.tsx` emulates that blur, and the graph e2e presses ArrowDown twice. The wait step chooser takes its wait id from queue.add’s result. The run’s goOn and decide controls stay in the renderer until B11. Word tasks with src/shared/model/words.ts, and mark them with `queueMarks` (`src/shared/model/queue-marks.ts`, imported directly) rather than adding another copy.

Canvas text uses `src/renderer/useDraft.ts`: its `useLabel` caps every name field at `MAX_LABEL` and restores a blank commit to its saved name; labels and group titles, agent names and roles, queue messages and instructions stay local while edited, committing on blur, single-line Enter or 600 ms idle. Escape cancels pending text; an unchanged field makes no graph change. Incoming changes leave a focused pending draft alone. Its window-wide `flushDrafts` commits pending fields and flushes React updates before another gesture reads the graph or starts work: pointer actions (drags and drops included), shortcuts, Run, the composer's Send, and shutdown's freeze/save. It also awaits commits still in flight (including those started on blur or idle); the GUI client awaits it before sending every operation and registers a draft's calls even if its UI callback returns void. A commit can send its own operation without awaiting itself. An optional flush callback runs after all attempts finish, synchronously when none is in flight. A field keeps its local text while the promises its commit returns or sends through `draftCall` settle (the client waits for their mirror revisions), including after blur or refocus. Validation runs while typing and before committing. An invalid draft or refused operation keeps its text and an error at the field until corrected or abandoned with Escape; a late settlement never revives an abandoned draft. Flushing waits for every attempt without letting one field’s refusal block another operation. Text selection, clipboard shortcuts and multiline Enter stay with the field.

The canvas's `arrange` setting is saved: absent in a `.corral` file means off, and only on is written. The core keeps it with the document and applies automatic layout after addAgent, spawnAgent, delete, link, unlink, group, ungroup and addParent while on, inside the same pure build and revision as that edit. Template insertion does likewise; turning Arrange on lays it out once. A structural no-op keeps empty revisions without running layout again. Explicit moves, renames, agent/queue edits and setting Arrange to its current value do not trigger layout. The renderer test canvas follows these same triggers. The renderer reads it from the mirror; selection, opening a panel and measurements never edit the document or its arrangement. Every node passed to React Flow carries `measured`: its overlay measurement if present, otherwise its model size (the fixed card or autosized container), so selecting a newly added node cannot erase its handle bounds before ResizeObserver runs. Agent cards follow the canvas-first guide: 186 × 73 CSS pixels (`CARD_SIZE`, the guide’s content height rounded from 72.5), checked against the stylesheet by `graph/card.test.tsx`. The first row has the catalog logo (an image from a data URL, never inline SVG, or the adapter’s first letter), the ellipsized name and a status dot; the next line names the status and current task or failure, then a progress bar counts finished authored top-level queue items, excluding blanks (no guessed progress inside a turn). `src/shared/model/run-display.ts` (`agentCard`, `agentStatus`, imported directly) shares status precedence with the dock: Needs first, individual pause controls, the live session, then its queue. Cards that need you glow; working dots pulse, Done is green, held cards dim, with reduced motion respected. Queue counts, pause badges and top/bottom handles stay outside; AgentTag and the adapter stripe are gone. The card’s title and its node’s accessible label keep the adapter and connection. Tests and e2e select the name through `.graph-label` rather than the card’s entire text.
