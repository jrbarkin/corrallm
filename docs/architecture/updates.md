# App updates

[Architecture index](overview.md) · [Canonical instructions](../../AGENTS.md)

`src/main/updates.ts` owns update policy; `src/main/host/updates.ts` adapts Electron's updater, signature inspection and native dialogs. Only the app's entry starts it, after its first window opens. The core, CLI and `corrallm serve` never check. Unpackaged builds (including e2e), the dev server and the native self-test never check either. `CORRALLM_NO_UPDATE_CHECK=1` disables both kinds of check until B22a provides settings. The feed and repository are constants in code, never renderer, environment or file input.

On macOS and Windows the app uses Electron's `autoUpdater` with the same [public feed](https://github.com/electron/update.electronjs.org#manual-setup) as update-electron-app: `https://update.electronjs.org/jrbarkin/corrallm/<platform>-<arch>/<version>`. It checks at launch, then every six hours, with no overlapping checks or repeated download while one is pending. This contacts update.electronjs.org with the app's version, OS and architecture in its URL; Squirrel downloads the chosen public GitHub release's package. The service requires a public repository and published releases; while the repository has no release, there is nothing to offer. Failures are logged once per distinct error in a launch, never shown as application failures.

Squirrel.Mac needs a signed app. A macOS build launched with `CORRALLM_UNSIGNED=1`, or whose executable has no Developer ID Application signature (ad hoc included), skips checks and says why once on stderr. The host inspects the executable's signature with `/usr/bin/codesign`; it does not trust an environment variable to assert signing. Windows retains the Squirrel path; its real installation and update checks remain held.

A downloaded update offers **Restart to update** and **Later**, defaulting to Later, once per release in a launch. GitHub release names may be titles rather than bare version tags, so a title still gets an offer without displaying arbitrary release text. No update restarts by itself. Restart asks main's quit coordinator for a quit of its own reason (`update`, `src/main/host/closing.ts`), joining a quit question or save already going on instead of issuing a second quit (which deliberately abandons a hung save); while work goes on it asks first, Restart and pause or Cancel (B14 C2), and Cancel clears the restart intent. Main's `Closing` path first has every window finish its drafts, then prepares the core's shutdown barrier for `update` (`AppUpdates.restarting`), and commits it. An approved quit, including Quit anyway after a save failure, awaits the core’s complete close without a timer: its session shutdown, verified child-group cleanup and store close must finish before quitting or installing. Only an explicit second quit, while saving or the core's close is stuck, uses the five-second escape (an update's restart joins the quit, never escapes it). Repeated quit events cannot skip this wait, only bound it that way, and late window-save results or an initial load aborted by window teardown cannot override the approved quit. A failed core close is logged and exits nonzero instead of installing. Only then does the approved quit call `quitAndInstall`. This ordering matters: [Electron closes windows before its usual before-quit event when quitAndInstall is called](https://www.electronjs.org/docs/latest/api/auto-updater#event-before-quit-for-update). If saving fails and you choose Keep corrallm open, the restart intent is cleared and installation is never invoked. Choosing Later leaves Squirrel's staged update for the next normal quit/start, without forcing a relaunch. The system's shutdown or logout taking over a restart installs nothing.

Keep running retains the core and its sessions; reopening from a notification uses the ordinary draft-flush and one-`window.show` switch, with local focus of a current Need only. It never restarts or installs an update, and the quit coordinator ignores reopen requests while an approved quit or update is saving. Every session process is closed before the core exits.

Linux packages do not use Squirrel. At launch, then at most daily, the app checks `https://api.github.com/repos/jrbarkin/corrallm/releases/latest`, without authentication or credentials, refusing redirects and with a ten-second bound including response decoding. HTTP 404 (no release) and 204 mean nothing to offer. A newer stable semver gets a native **corrallm X is available** dialog with **Open release page** and **Later**, defaulting to Later, once per version in a launch. Drafts and prereleases (including prerelease tags) are ignored; build metadata alone does not make a version newer. The request's User-Agent contains corrallm's version and Linux architecture. No token, canvas, project folder, agent or session data is sent by either check. The normal network connection also exposes its source IP to the contacted service.

The Linux release link is constructed from the fixed repository and validated version tag, ignoring the response's html_url. Main sends it on its private core link for a connected window; `WindowPorts.openLink` dispatches the existing `link.open` as that window's human caller. `src/main/links.ts` applies the same URL normalization and policy as any clicked link before the host opens it; the updater never calls shell.openExternal directly. This host-only request adds no renderer channel or operation.

All updater events, clocks, fetches and dialogs are injected in unit tests. Tests cover the gates, fixed feed, signature inspection, scheduling, duplicate offers, bounded requests, semver comparisons and release-link construction. Main's tests hold renderer acknowledgement, core flush and core close independently and prove installation waits for all three, including a nine-second close after a successful save or Quit anyway, and a second quit's five-second escape from a close that never settles; they also cover both renderer and core save failures with Keep corrallm open. Timers and listeners stop when the app quits, and an in-flight Linux check is aborted.

## Channels and the rehearsal

The release asset names are pinned by `build/release.ts` and checked against update.electronjs.org's rules (the zip and dmg names were seen from a real make; the deb and rpm names are derived from the installers' own code, which `build/release.ts` mirrors, and not yet seen from one): the macOS asset is `corrallm-darwin-arm64-<version>.zip` (the service takes a `.zip` naming `-darwin`, `-mac` or `-osx`, reads the architecture from `-arm64`, `-x64` or `-universal`, and serves a name with none to Intel Macs). The zip holds the stapled app. A beta's Linux packages are published with a `.` where the package's own version has a `~` (`corrallm_0.1.0.beta.1_amd64.deb`): GitHub rewrites a `~` in an asset's name on upload, so the script renames the files before it writes `SHA256SUMS`, which then names them as they are stored. The version inside the package keeps its `~` and still sorts before the release. No Windows asset is attached while Windows is held. A beta is a GitHub prerelease: the update service serves only the latest stable release and the Linux check ignores prereleases, so publishing a beta offers it to nobody, and a beta copy updates to the next stable release (`0.1.0` is newer than `0.1.0-beta.1`).

Once a stable release is published, every signed copy installs it at its next restart, which is why only the maintainer publishes (see [toolchain](toolchain.md), Releases). Squirrel.Mac installs an update only if it satisfies the running app's designated requirement: the same team and bundle id. The first signed release fixes both for every copy installed after it.

Squirrel can replace the app only from /Applications; run from a translocated or read-only location it logs that once and cannot update. The launch README's install section (held until launch) is to say to drag corrallm to Applications. There is no host behaviour for this.

Before the first beta, an update is rehearsed with two signed scratch builds whose feed constants (`SERVICE`, and `LATEST` for Linux, in `src/main/updates.ts`) point at a server on 127.0.0.1 serving Squirrel.Mac's JSON and the second build's zip: the first is installed in /Applications, the offer is seen, Restart to update is chosen while a run works (which brings up the quit question), and the second version is confirmed to run with its profile and paused run intact. Those builds are never committed or distributed. After the first stable release, a read-only request to `https://update.electronjs.org/jrbarkin/corrallm/darwin-arm64/<an older version>` shows the service's choice of asset, and a beta copy is watched updating. Neither can run without a Developer ID, so neither is done by the release script or its tests.
