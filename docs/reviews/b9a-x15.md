# B9a X15 adversarial review

Reviewed on `feat/b9a-x15`, baseline `0d0fc4d`, including #115's creation-time marker and #121's selector/workspace-safety work. Production code remains unchanged. These are bounded probes, not a claim of exhaustive filesystem or process isolation.

## Findings awaiting C

### F1: an unmarked population can overwrite later work

In `src/main/core/workspaces/provision.ts`, the `registered` phase is replayed with `read-tree --reset -u` until `populated` is durable. A real-Git probe completes population, interrupts before its phase write, edits the tracked README while the core is down, and reconciles. The edit becomes the base's `hello` again. No agent was admitted while creating; this finding specifically concerns work added to the exposed checkout after that crash.

The preservation assertion fails. With a durable `populated` phase, the paired integration test preserves both tracked and untracked work. C must decide how to recognize/adopt a completed or partial population and how to hold an uncertain dirty checkout for recovery without automatically resetting it. This review adds no recovery policy.

### F2: Git metadata symlinks escape the checked root

The owned-root walk refuses a linked `.corral`, but mutation in `src/main/core/workspaces/provision.ts` does not similarly contain Git's metadata writes. Two real-Git probes show the boundary:

- A pre-existing symlink from the common directory's `worktrees` directory to an outside folder receives a new registration directory. The later checkout check refuses it, after the outside write.
- Moving `refs` outside and linking it back lets creation write the generated branch outside the common directory and finish in `setup`.

Both no-outside-write assertions fail. The UUID checkout itself remains below the owned root; the escape is in Git metadata. C must settle the supported metadata layout and validate mutation destinations before Git runs. Checking just the final checkout after mutation does not prevent these writes. This is broader than #115's inode-reuse repair; that repair's replacement-root tests pass.

### F3: cleanup assessment runs a submodule's clean filter

`src/main/core/workspaces/cleanup.ts` assesses status using `--ignore-submodules=none`. Its driver list comes from the picked checkout and workspace, not the initialized submodule. With a real gitlink, an initialized submodule whose local config declares an evil clean driver, and a same-length edit to its tracked text file, merely calling `assess` executes the sentinel program. No setup or discard approval is involved.

The no-program assertion fails. A different-length edit initially did not reproduce it: Git could decide dirty from metadata without hashing. The corrected same-length probe forces the content path. C must choose a safe submodule-assessment contract; simply ignoring submodules could incorrectly classify their work as safe to discard. Token-triggered deletion preflights should be considered when reviewing this service path. This probe establishes assessment execution, not an independently exercised token exploit.

## Suspicions not confirmed

- Conditional includes enabling a new filter only on the generated branch: provisioning reinspects configuration inside the new checkout before population. The existing hostile-repository provisioning test passes, including branch-conditional drivers.
- Inode reuse alone adopting a replacement root: #115 includes creation time and refuses absent creation identity/nonempty inode-only legacy roots. The owned-root replacement tests pass. Empty-root adoption is the explicit C policy, not a finding.
- Copying a dirty manifest's extra secrets, traversing links, or overwriting tracked/copied files: the real-Git copy/fault tests pass. The new combined integration case reads only the captured manifest, excludes an unselected ignored secret and keeps copied values out of Needs and token listings.
- Interrupted Always approval replaying automatically: the new real-Git/store test persists a running approved attempt with Always, then recovers/reconciles. It remains interrupted, offers a card and never spawns.
- A stale discard deleting changed work: the new real-Git retained-tree test refuses after the file changes. Existing cleanup and planner tests also pass. The app spec adds stale proposal, re-question, Keep and fresh Remove coverage.
- Token setup control or private workspace fields: service replies reject real agent party ids; the listing omits path, card, setup and errors and kept trees. Registered human-only removal/reach tests run separately. No new authority was added.
- Store generation reuse, changed job identity or malformed record admission: existing workspace-store tests pass; the durable high-water mark, immutable intent hash and fail-closed readers remain in place.

## Shipped tests and app gate

`src/main/core/workspaces/integration-edges.test.ts` adds five passing cases: durable-phase recovery preservation; two-canvas real-Git serialization; captured-manifest copying plus token redaction/reply refusal; interrupted Always recovery; stale retained-tree discard.

`e2e/worktrees.e2e.ts` adds eight app cases: independent branches/native cwd/conversation reuse/base and canvas-file hygiene; shared native cwd/files with distinct conversations; hostile hooks/filters/fsmonitor; core.worktree refusal; symlinked .corral refusal; a core crash after real Git population but before phase marking; project replacement with live native sessions; and stale cleanup proposals followed by Keep and explicit Remove. The crash uses a fixture Git wrapper that runs real Git, then holds exactly once until the test kills the core. No production fault hook is added. The ordinary crash fixture leaves its checkout unmodified; F1's dirty variant is a separate failing probe.

Run the new spec alone with `pnpm test:e2e e2e/worktrees.e2e.ts --retries=0`. Reuse the build for X14's `e2e/workspaces.e2e.ts` and X13's `e2e/template-workspaces.e2e.ts`, each alone. Those already cover shared groups, non-Git folders, setup controls, deletion Keep/Discard and relay templates. Full native/Linux/package gates, Q32 recheck and G2 with provisioned workspaces remain C's release work; this sandbox executes none of them and makes no Windows claim.

## Reproducing the findings

Place the following files under node_modules/.cache/probes and run `pnpm exec vitest run --config node_modules/.cache/probes/134.config.mts`. All four assertions fail on the reviewed baseline. They stay outside the ordinary suite so known unresolved security failures are not turned into passing expectations or silently skipped shipping tests.

134-review.test.ts:

```ts
import {
  mkdirSync,
  readFileSync,
  readdirSync,
  renameSync,
  symlinkSync,
  writeFileSync,
} from 'node:fs';
import path from 'node:path';
import { afterEach, expect, it } from 'vitest';
import {
  testWorkspaces,
  CANVAS,
  PROFILE_ID,
} from '../../../../src/main/core/workspaces/test-workspace';
import type { TestWorkspaces } from '../../../../src/main/core/workspaces/test-workspace';
import { GitRunner } from '../../../../src/main/core/workspaces/git';
import type { GitCall } from '../../../../src/main/core/workspaces/git';
import { Provisioner } from '../../../../src/main/core/workspaces/provision';
import { WorkspaceCleanup } from '../../../../src/main/core/workspaces/cleanup';
import {
  git,
  commit,
  makeRepository,
  ran,
  sentinelProgram,
} from '../../../../src/main/core/workspaces/test-git';

let t: TestWorkspaces | undefined;
afterEach(async () => {
  await t?.close();
  t = undefined;
});

it('keeps dirty tracked files after population finished but its phase was not marked', async () => {
  const w = (t = await testWorkspaces());
  class Crash extends GitRunner {
    override async run(call: GitCall) {
      const result = await super.run(call);
      if (call.args[0] === 'read-tree') throw new Error('crash before population mark');
      return result;
    }
  }
  const first = new Provisioner({
    workspaces: w.workspaces,
    git: new Crash(w.runnerDeps),
    profile: PROFILE_ID,
  });
  await expect(
    first.provision({ canvas: CANVAS, repository: await w.repository(), owner: 'agent/builder' }),
  ).rejects.toThrow('crash before population mark');
  const tree = w.workspaces.worktreesOf(CANVAS)[0];
  if (!tree) throw new Error('No intent');
  expect(w.workspaces.openJobs()[0]?.phase).toBe('registered');
  writeFileSync(path.join(tree.path, 'README.md'), 'work added after crash\n');
  await w.provisioner.reconcile();
  expect(readFileSync(path.join(tree.path, 'README.md'), 'utf8')).toBe('work added after crash\n');
});

it('does not write Git registrations through a symlink outside the picked repository', async () => {
  const w = (t = await testWorkspaces());
  const outside = path.join(w.root, 'outside');
  mkdirSync(outside);
  symlinkSync(outside, path.join(w.app, '.git', 'worktrees'));
  const tree = await w.provisioner.provision({
    canvas: CANVAS,
    repository: await w.repository(),
    owner: 'agent/builder',
  });
  expect(tree.state).toBe('error');
  expect(readdirSync(outside)).toEqual([]);
});

it('does not execute a submodule’s clean filter while assessing cleanup', async () => {
  const w = (t = await testWorkspaces());
  const sub = path.join(w.app, 'sub');
  const files = { '.gitattributes': '*.txt filter=evil\n', 'data.txt': 'base\n' };
  const oid = makeRepository(sub, w.env, files);
  git(w.app, w.env, 'update-index', '--add', '--cacheinfo', `160000,${oid},sub`);
  commit(w.app, w.env, 'gitlink');
  const { tree } = await w.provision();
  const checkout = path.join(tree.path, 'sub');
  makeRepository(checkout, w.env, files);
  const sentinel = path.join(w.root, 'ran');
  const program = sentinelProgram(w.root, sentinel);
  git(checkout, w.env, 'config', 'filter.evil.clean', program);
  writeFileSync(path.join(checkout, 'data.txt'), 'evil\n');
  await new WorkspaceCleanup({ workspaces: w.workspaces, git: w.git }).assess(tree);
  expect(ran(sentinel)).toEqual([]);
});

it('does not write generated refs through a symlink outside the common Git directory', async () => {
  const w = (t = await testWorkspaces());
  const outside = path.join(w.root, 'outside-refs');
  renameSync(path.join(w.app, '.git', 'refs'), outside);
  symlinkSync(outside, path.join(w.app, '.git', 'refs'));
  const before = readdirSync(outside, { recursive: true }).sort();
  const tree = await w.provisioner.provision({
    canvas: CANVAS,
    repository: await w.repository(),
    owner: 'agent/builder',
  });
  expect({ state: tree.state, files: readdirSync(outside, { recursive: true }).sort() }).toEqual({
    state: 'error',
    files: before,
  });
});
```
